## 一、规则缺口（已回灌 CAW）

| # | 现象（本项目踩到的） | 缺什么规定 | 建议补在 |
|---|---|---|---|
| G1 | R7 只说 boot/manual「两态互斥的一等模式」，没说档位是**注册层配置**还是**运行期状态**。按"运行期可切"设计后，衍生出交接执行者、目标档位歧义、回切无路径等一串问题 | 明写：档位 = **注册层配置**；切换只改注册层、**下次启动生效**，当前实例身份不变；判定以「任务是否**启用**」为准（不要求删除），因为删除对运行中实例的影响未定义 | R7 |
| G2 | R10 要求「监督者重试循环 MUST 在顶班退出后自动接棒」，但没说监督者若只能**周期触发**（Windows 任务计划的 Repetition）时，如何与「用户主动停止服务」共存。按字面实现周期重试后，用户刚点的"停止"会被 5 分钟后自动拉起 | 明确两种合法形态：①**不实现周期重试**——接棒推迟到下一次系统启动（需在文档里声明这是取舍）；②**周期重试 + 用户抑制标记**，且标记必须带**开机周期标识**（不能只存时间戳，快速启动下 uptime 不归零） | R10 |
| G3 | I8「退出码 0 = 监督者不得重启」只对**事件式**监督（失败重启）成立；对周期触发型监督者，退出码与是否重启无关 | 限定 I8 的适用面：事件式监督用退出码表达"不要重启"；周期触发型必须用**显式抑制标记**表达，不能用退出码 | I8 / R3 |
| G4 | R5 交接写成「注册 → 退出 → 探测释放 → 启动监督者条目」，第 2 步之后当前核心已经死了，第 3/4 步**没有执行者** | 明写：交接中"当前核心退出"之后的步骤，必须由**非当前核心的进程**执行（唤醒进程 / 派生的一次性切换器 / 监督者本身）；禁止"核心在自己退出后继续执行后续步骤"的写法 | R5 |
| G5 | AP9 只写了"提权核心不许**写** per-user 注册存储"，没说**读**。SYSTEM 核心读 HKCU 读到的是自己的蜂巢 → 恒 false，导致助手反复"修复"一个本来正常的项 | 注册物按**所有者**划分：per-user（HKCU / systemd user unit）只能由**会话内助手**读写；per-machine 只能由提权核心/安装器读写。**跨所有者的读同样禁止**（读到的是别人的蜂巢/作用域） | AP9 / 新增一条 |
| G6 | I4 只说"用探测 + 系统级互斥/锁保证"，没提 Windows 上创建 `Global\` 命名对象需要 `SeCreateGlobalPrivilege`——标准用户/未提权管理员**创建**会 `ERROR_ACCESS_DENIED`（SDDL 只约束打开，不解决创建） | 平台映射表补一行：单实例原语在 Windows 上不要用 `Global\` 命名对象，推荐 `%ProgramData%` 下的 per-machine 文件锁（`LockFileEx`，句柄关闭即释放，崩溃不留死锁） | 「平台映射」表 + I4 |
| G7 | 评审清单「凭据/私钥对两种身份都可读——首跑即按机器级创建」没给**交互用户身份**的来源。零登录会话里 SYSTEM 首跑时无从得知"交互用户"是谁 | 补：交互用户身份由**安装器写入**机器级元数据（如 `install.json` 的 SID）；取不到则退化为按组授权（`Users:R`）并**打降级标记** | §4 评审清单 |

## 二、MSO 的缺口（已回灌）

| # | 现象 | 缺什么规定 | 建议补在 |
|---|---|---|---|
| M1 | §6 只要求"机检接入 CI"，没要求机检自身可自证。实际写出来的规则会被注释、组合导入（`use crate::{a::X}`）、`#[path]` 模块重定向、别名/取函数引用等写法绕过 | 补：机检必须带 `--selftest`，且自测用例要覆盖**已知绕过形态**（注释、组合导入、路径重定向、别名与取引用）；自测必须进门禁 | §6 |
| M2 | 「每条环必须有终止保障」没说清是**环级**还是**节点级**。实现成"环上每个模型都要声明"会把正常的双向只读询问判成违规 | 明确是**环级**：环上任一模型声明终止保障即可；并允许"纯只读 port"显式声明相位（不构成需要终止保障的环） | 三条核心纪律 1 |
| M3 | 没规定"机检采信的声明必须是代码级"。用注释 `// termination: phase` 就能满足机检，等于没有约束 | 补：任何被机检采信的声明必须是**代码级**（常量 / 属性 / 实际函数调用），注释不算 | §6 |

## 三、本项目的解读与偏离（不要求回灌）

| 项 | 本项目的做法 | 依据 |
|---|---|---|
| R7 双档位 | 只做**一个开关**「开机自启」，不做运行期身份切换；改档 = 改注册层 + 重启生效 | 见 G1 |
| R10 顶班 | 采用 R10 的"拉起用户态核心"，但**不实现周期重试**，接棒发生在下一次系统启动 | 见 G2，与"停止服务即停止"的语义冲突 |
| R11 合并形态 | 不采用：有桌面会话与托盘，分离可成立；合并即 AP1 | R11 原文"仅在无法分离时允许" |
| 凭据 | machine-scope DPAPI + 安装器写交互用户 SID；不读 `~\.ssh` | 见 G7 |
