# 没有肉眼时的界面自检

> 界面改动不靠"看起来对不对"，靠一条可重复的回路：**构建 → 启动 → 抓图 → 看图 → 改**。

## 回路

```
powershell -File scripts/shot.ps1     # 抓当前 tl-agent 窗口到 %TEMP%\tl-ui.png
```

脚本要点（踩过的坑都在里面）：

- 必须 `SetProcessDPIAware()`，否则裁剪坐标与物理像素差一个缩放倍率，右侧永远被切；
- 用 `PrintWindow(..., PW_RENDERFULLCONTENT)`，锁屏 / 会话切换时 `CopyFromScreen` 会失败；
- 窗口先 `ShowWindow(SW_RESTORE)` + `SetForegroundWindow`，再等 ~1 秒让 WebView 完成绘制。

## 看图时固定查这几项

| 检查项 | 反例 |
|---|---|
| 横向溢出 | 卡片右边界消失、按钮被窗口边缘切掉 |
| 语义与状态一致 | 状态写着"未连接"，主按钮却写着"断开连接" |
| 重复信息 | Hero 里复述一遍下面已经有的完整错误 |
| 文字截断 | 长路径/长错误把行撑爆，或截断到看不出是什么 |
| 空状态 | 只有一句"暂无数据"，没告诉用户下一步 |

## 局限

- 看不到 hover 态、弹窗、滚动后的内容。需要时用 `SetWindowPos` 把窗口拉高（本项目 1582×1340
  在 2560×1440 / 150% 下能看完整张卡片），或者临时把页面滚动位置调到目标区域。
- 截图只能证明"渲染出来了"，不能证明"点得通"。交互路径仍要单独验证（接口 / 日志 / 状态变化）。
