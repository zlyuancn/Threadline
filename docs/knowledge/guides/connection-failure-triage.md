# 「连不上」怎么定位

SSH 本地转发有五个可能断的环节，报错信息必须能指到**具体哪一环**，否则用户只能猜。
我们的探测（`engine::probe` / `POST /servers/{id}/probe`）就是按这五层设计的。

## 1. 分层与判据

| 阶段 | 判据 | 典型原因 |
|---|---|---|
| `tcp` | TCP 连不上或超时 | 地址/端口写错、服务没起、防火墙丢包 |
| `ssh` | TCP 通，但对方没有给出 `SSH-` 横幅 | 端口是 HTTP/SMTP 之类；或对端把包丢了 |
| `fingerprint` | 握手成功，主机密钥与记录不一致 | 换了机器、中间人或被劫持 |
| `auth` | 握手成功，认证被拒 | 用户名/密码/私钥不对，或服务器不允许该方式 |
| `ok` | 三层都过 | —— |

实现细节：探测先**单独开一条连接读横幅**（读完即关，不影响随后的 russh 握手），
这样"对方先说话但不是 SSH"与"对方根本不说话"能被区分开——两种情况的处理完全不同。

## 2. 用命令行对照，别只信程序的结论

```
ssh -p <port> <user>@<host>
```

- 命令行能连、程序不能连 → 问题在本机（见第 3 节）或凭据不同（`~/.ssh/config` 可能指定了另一个私钥）。
- 两边都不能连 → 先看 `ssh -v` 卡在哪一步，与上面的分层对齐。

顺带检查 `~/.ssh/config`：抓过 `Host` 别名里写死不同端口的情况，用户以为在测 A，实际测的是 B。

## 3. 同一台机器，不同程序结果不同 → 大概率是安全客户端按路径拦截

实测矩阵（同一时刻、同一目标）：

| 客户端 | 结果 |
|---|---|
| `ssh.exe`（终端） | 登录成功 |
| PowerShell / Python / Node 直连 | 收到 `SSH-2.0-OpenSSH_10.0` |
| `tl-core.exe` 从 `target\debug\` | HTTP 403（网关拒绝页，`code:190001`） |
| **同一份** `tl-core.exe` 从 `%TEMP%` | 收到 `SSH-2.0-OpenSSH_10.0` |
| 安装版从 `%LOCALAPPDATA%\Threadline\` | HTTP 403 |

结论：**可执行文件的启动位置决定是否被拦截**，与代码、与目标无关。
拦截结果被包装成远端响应，所以程序只能如实说"收到的不是 SSH 横幅"。

处置：
- 把安装目录加入安全软件白名单（这是唯一根治方式）。
- 临时验证可以换到允许的目录跑同一份二进制，确认不是代码问题。

## 4. 「连上了但没反应」与「连不上」

这两种要分开：

- **转发通道打不开**（服务器侧连不上目标）→ 我们会在 `last_error` 里写
  `无法连接 <host>:<port>（服务器侧）：Failed to open channel (ConnectFailed)`，**不改状态**
  （SSH 会话还好，其他连接照常）。
- **通道打开了但目标不回包** → 表现为本地连接一直挂着。这类挂起加了 10 秒上限
  （`CHANNEL_OPEN_TIMEOUT`），超时报"服务器在 10 秒内没有确认通道（目标不可达或被防火墙丢弃）"。
  没有这个上限时，用户只看到"连上了没反应"，而且永远不会有错误记录。

## 5. 状态与意图必须分开

- 开关 = **用户意图**（持久化，重启继承）
- 状态列 = **现实**（运行中 / 重连中 / 错误）

启动失败**不回滚意图**：连不上是网络或目标的问题，不该篡改"用户希望它开着"这件事。
否则用户会遇到"我明明开了，它自己关了"这种无法解释的行为。

## 4. 「已连接」与「运行中」是两套事实，会互相打脸

- 隧道行看的是 **SSH 会话是否活着**（`session_connected`），转发卡片看的是
  **监听任务自己的状态机**。两者由不同代码维护，掉线时不会同时更新。
- 典型症状：隧道「未连接」，转发「运行中 · 暂无连接」，本地端口仍然被占。
- 原因：转发任务的循环挂在 `accept()` 上，**没人连进来就永远不会发现会话已经死了**。
- 判定方法：查 `session_connected()`；如果它 false 而转发 state 仍是 `running`，就是僵尸状态。
- 处理原则：**以会话为准**。会话不可用时主动停掉挂在它下面的转发（释放端口、状态回落并写明原因），
  重连后按"掉线前真在跑的那批"恢复——不要按 `auto_start` 猜，那是用户意图，不是当时的实际状态。
