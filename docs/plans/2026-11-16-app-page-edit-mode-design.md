# 应用页编辑模式 · 设计

> 状态：**已拍板**（2026-11-16，用户要求「应用页面提供编辑模式，能快速拖动、快速修改增加分组」）

## 目标

应用页不只是"看"，还能**摆**：拖动磁贴调整顺序与归属，就地改分组，分组本身也能新建 / 改名 / 删除 / 排序。布局存核心，与配置一起走（重装、换机都在）。

## 边界（先说清不做什么）

- **不碰端口转发**：新增的 `app_order` 与分组清单只被应用页读取，`fsm`、监听、会话、hosts 生成都不引用它们。改布局不会动任何一条转发。
- **编辑模式只管布局**：名称、图标、端口、域名仍在转发编辑弹窗里改，避免同一个字段有两处入口。
- 不做磁贴自由定位（x/y 坐标）——网格顺序足够，坐标布局在有响应式列宽时必然错位。
- 不做拖拽改变分组内的"多选批量"，一次拖一个。

## 数据

| 数据 | 位置 | 说明 |
|---|---|---|
| 磁贴顺序 | `TunnelDto.app_order`（`i32`，缺省 0） | 越小越靠前；全 0 时按列表原顺序稳定排序（旧配置零迁移） |
| 分组清单 | `%PUBLIC%\Threadline\app_groups.json` | `{ schema_version, items: [{ name, order }] }`，负责**顺序**与**空组** |
| 成员归属 | `TunnelDto.group`（既有字段，空 = 未分组） | 唯一真相不变；转发逻辑本来就不读它 |

**自动收录**：`GET /app-groups` 返回清单 + 转发上出现但清单里没有的组名（按首次出现补到末尾），手改配置不会让组消失。
**迁移**：文件不存在时按现有转发 `group` 的首次出现顺序合成，首次写入时落盘。
**未分组**：隐含组，永远排最后，不可改名/删除；组名不能为空、不能重名、不能叫「未分组」。

## 接口（5 个，语义原子）

```
GET  /api/v1/app-groups                 分组清单（含自动收录与空组）
PUT  /api/v1/app-groups                 全量清单：新建、删空组、调整组顺序
POST /api/v1/app-groups/rename          {from,to} 改名 + 成员一起改（核心一次写完）
POST /api/v1/app-groups/delete          {name} 删组 + 成员回落未分组
PUT  /api/v1/tunnels/app-order          {ids} 磁贴全局顺序（缺席追加末尾）
```

排序口径（核心统一）：组顺序 = `order`（未分组恒最后）；组内顺序 = `app_order`。

## 交互

1. 应用页标题右侧「编辑」开关；进入后搜索框清空、`showAll` 强制打开（过滤视图下拖动会算错顺序）。
2. 磁贴盖一层可拖区域（同时挡住"点一下就打开浏览器"）；组头出现**排序按钮**（置顶 / 上移 / 下移 / 置底）与「删除」、组名可点改名；页尾出现「新建分组」。
   组排序不用拖动：组头横条太窄，拖动难命中；组数量少，四个按钮一步到位更省事，首尾还能直接置灰。
3. 拖动：**指针事件实现**（`pointerdown/move/up` + `elementFromPoint` 判定落点），不用 HTML5 `draggable`——Windows 上 Tauri 接管原生拖放，`dragstart` 根本不会触发。落点用磁贴左右半边决定插前/插后，组容器空白处表示追加到该组末尾。
4. 拖动磁贴：先按落点算新顺序，跨组时再 PATCH 归属，最后 `PUT /tunnels/app-order` 提交全量顺序；任一步失败 → 重新拉取并提示，界面回到服务端事实。组排序按钮则走 `PUT /app-groups` 全量重排（已在边界时按钮置灰，不发请求）。
4. 磁贴上的分组入口用 `el-select`（`filterable allow-create`）：选已有，或输入新名字立刻建组。
5. 新建分组：先落一个空组到末尾，再把应用拖进去。

## 分层

| 位置 | 职责 |

## 验收

1. 进编辑模式 → 拖动一个磁贴到另一组 → 松手后刷新页面顺序仍在，组归属已改。
2. 组内拖动排序 → 刷新后保持；「未分组」始终在最后。
3. 新建空组 → 出现在末尾且刷新后仍在；拖一个应用进去 → 组内有成员。
4. 重命名组 → 组名与其所有成员的 `group` 同时变；成员不丢。
5. 删除组 → 该组成员回到「未分组」，其它组不受影响。
6. 拖动组顺序 → 刷新后保持。
7. 改布局后，正在运行的转发不停、端口不变、hosts 不变（对拍一次 `GET /tunnels` 的状态与 local_port）。
